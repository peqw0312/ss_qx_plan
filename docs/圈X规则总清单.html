这是「国内不卡」的根基：所有规则都没命中 → 直连
一个反直觉、但很重要的结论：国内 App 不需要为它们写规则。
银行、社交、金融、股票基金这类国产 App（工行 / 招行 / 支付宝 / 微信 / 东方财富 / 同花顺 …）， 它们的域名本来就不在「全球加速」名单里 —— 那份名单是「被墙域名清单」，只收 Google、GitHub、X、YouTube 这类。
所以国产 App 的请求会天然掉到最后那行 final, direct → 直接直连，第一关就定死。
给它们额外写规则 = 空转，不产生任何效果，只增加规则数量。
⚠ 但这个结论有一个「但书」—— 豆包就是这么中招的（第十八轮）。
「不用写规则」成立的前提是没有任何其它规则会命中它。而远程「广告终结者」（Cats-Team/AdRules） 里夹着一条 host-suffix, opt.doubao.com, reject —— 唯一一条命中豆包的规则。
opt.* 是字节的 ABTest / 配置下发域名，豆包启动时要请求它拿实验分组和功能开关， 被 reject 之后可能重试 + 等超时 → 启动和首页内容变慢。
所以「要不要给某个 App 写规则」的正确问法不是「它是不是国产的」， 而是「有没有哪条规则会命中它」。远程规则集是别人维护的、会变， 这就是第十八轮要给字节系「钉死」直连的原因。

· 原理：Soul 的属地由出口 IP 判定 → 让流量走境外节点，属地就显示成那个国家

作者加它是为了让油管 / 小红书去广告生效 —— 圈X 的 URL 重写抓不到 QUIC（加密、不走 TCP），不丢 QUIC 的话很多 App 会偷偷用 HTTP/3 加载广告。
