先搞清楚你要看的那一列：策略。
这份清单里几乎所有验证，都是看同一件事 —— 请求记录里的「策略」列。
打开方式：圈X → 首页左上角的三横线（或底部的图表图标）→ 网络活动 / 请求记录 / Activity （不同版本叫法不同，找带「活动」「记录」「日志」字样的那个）
打开后每个请求会显示：域名 · 时间 · 策略 · 流量。策略这一列就是答案。

零、动手测试前，先确认 3 件事

这三件不做，后面测出来的结果没有意义。

① 确认配置不会被自动覆盖回原版
去这里设置 → 配置文件
看什么当前生效的配置是哪个？是「从文件导入」的本地配置，还是通过 URL 添加的远程配置？
判断 · 如果是本地导入 → 安全，不用管
· 如果是URL 添加的 → 必须关掉它的自动更新开关。否则它会把你的定制版覆盖回墨鱼原版，所有改动归零。
② 检查 MitM 证书还在不在 —— 决定去广告能不能生效

这不是多余的担心：证书信息（p12= 和 passphrase= 两行）是你本地生成的，不在下载的配置文件里。换配置文件时它有可能丢。

去这里设置 → MitM
看什么顶部有没有证书信息？「证书信任」是不是正常状态？
判断 · 有证书 → 跳过，去下一项
· 没有证书 / 提示未生成 → 点一次「生成证书」。系统的信任通常还在（根证书没换）；如果 App 提示证书失效，需要重新下载描述文件并在 设置 → 通用 → 关于本机 → 证书信任设置 里打开它。
为什么这件事一定要做：9 条重写里，去开屏、油管、微博、知乎、网易云、B站 这几条都要靠 MitM 解密才能生效。 证书不在，它们就是摆设 —— 这也是很多人「装完发现去广告没效果」的真正原因。
③ 看一眼策略组里有没有节点
去这里圈X 首页（就是显示各策略组和节点延迟的那一屏）
要确认 1. 「自动选择」组里有节点、有延迟数字 —— 说明节点订阅正常
2. 新加的 韩国节点 / 英国节点 / 大马节点 / 德国节点 / 火鸡节点 五个组里有没有节点
3. 「Soul」组和「交易所」组是否正常显示
4. 顺手看一眼 大马节点 的图标 —— 是不是已经变成和其它地区组一样的正方形（原来是长方形）
不符预期 五个新地区组里有空的 → 说明你的节点名里不含匹配关键词（如「韩 / KR / Korea」）。给节点改个名（在节点上长按 → 重命名，加上地区字）就会自动归组。 它们匹配的是：韩|KR|Korea|Seoul · 英|UK|Britain|England|London · 马来|大马|MY|Malaysia|Kuala · 德|DE|Germany|Frankfurt|Berlin · 火鸡|土耳其|TR|Turkey|Istanbul

8 豆包专项本轮修复 重新导入这次的新配置后，打开豆包 App：

顺手看：首页 → 网络活动 / 请求记录，搜 doubao		 预期：启动变顺、出字更跟手。 ✅
请求记录里 doubao.com / opt.doubao.com 显示 direct，不再有红色的 reject / 拦截标记。

这一项修的是什么：远程「广告终结者」里有一条 host-suffix,opt.doubao.com,reject —— 唯一一条命中豆包的规则。opt.* 是字节的 ABTest / 配置下发域名，豆包启动时要请求它拿实验分组和功能开关， 被拦掉之后可能重试 + 等超时 → 你觉得「卡」。

不符预期：如果 opt.doubao.com 那行显示的还是拦截 → 新配置没生效，重新导入一次。

· 讯飞输入法
· 百度输入法

顺手看：首页 → 请求记录，搜 sogou / iflytek / baidu		 预期：语音识别正常出字，请求记录里相关域名显示 direct。 ✅
为什么专门验这个：输入法的「云输入 / 语音识别 / 词库同步」都要连国内服务器，而远程「广告终结者」里夹着 28 条 *.sogou.com 的 reject，而且它每天更新 —— 平时拦的是广告和埋点，一旦误伤到功能域，表现就是「语音输入没反应」，你根本想不到是代理配置干的。
本轮已把搜狗 / 讯飞 / 百度 / 手心 / QQ 输入法、以及讯飞与百度的语音识别 API 显式钉为直连（见规则总清单 #61–#82）。

不符预期（语音没反应 / 一直转圈）：先看请求记录里那个域名显示什么 ——
· 显示 reject → 远程广告规则又更新了，把 rules/domestic-direct.list 里对应的域名补进本地规则；
· 显示 节点名 → 是分流问题，把域名发我。
只是「慢一点」是正常的 —— 语音识别本身要上传音频、等云端返回。

三、整体感觉「还是卡」怎么办

按这个顺序排查，三步就能定位到原因。

核心四项都测完，结果怎么算正常？
第 1 项是 direct、第 2 项是 Soul、第 3 项是 代理应用、第 4 项 App 能正常用 —— 四个都对上了，这次改造就成功了，你已经拿到了「国内直连 + 点名服务走代理 + 部分去广告」你想要的效果。
第 8 项（豆包）是第十八轮补的专项、第 9 项（输入法语音）是第十九轮补的 —— 验完这两项，就知道那两条 reject 是不是真的修掉了。

四、把结果发我时，怎么发最省事

不用截图全部，只要这四样里对不上的：

  1. 哪个 App（或哪个网站）
  2. 它现在的表现（打不开 / 很慢 / 属地没变 / 还有广告）
  3. 请求记录里的域名（比如 api-h5.soulapp.cn）
  4. 那一行显示的策略（direct / 节点名 / Soul / 代理应用）

有这四条，我就能直接定位是规则没覆盖、被别的规则抢先、还是节点本身的问题 —— 不用再来回猜。
