二、为什么你感知不明显

  • 12 条里有 10 条是单 App 专用的。你没装、或很少用的 App，装了等于没装。
  • 两条必须卸载重装才生效（高德地图、闲鱼）。作者在名字里标了「卸载重装」，多数人不会做这步，于是这两条一直是废的。
  • 开屏广告只能去一部分。很多 App 的开屏是本地资源或走非 HTTP 通道，重写拦不到。
  • 远程重写是别人维护的，会失效。作者的更新日志里反复出现「新版已无需重写」「已失效」「年久失修故删除」——你这份是 2026/09 的，里面的重写跟没跟上 App 新版本，没人保证。
  • 它天生没有「效果感」。去广告不会告诉你「我拦了 3 个」，你只是看不到广告而已。

三、反直觉的一点：去广告本身可能让你觉得卡

广告请求被掐断后，App 往往不会立刻放弃，而是重试或等超时再渲染页面 —— 首屏反而更慢。

开屏广告被拦掉后，App 要等一个兜底超时才能进主页 —— 你的感受是「卡在启动页」。

你感知不到收益，却在为它付卡顿的成本。那它对你就是负收益，应该砍掉大部分。

四、卡顿排查：三步，全部不用改配置文件

1
看请求记录，判断国内流量走的是哪条路
圈X 里找「请求记录 / 网络活动」入口，打开一个国内 App（淘宝、微信、抖音）刷几下，回来看这些请求的「策略」一列。
显示某个节点名 → 确诊「国内流量绕道出国」。这是最贵的一种卡，去把 GeoLite2 数据库配好（见上一份方案）。
显示 direct → 分流没问题，看第 2 步。
2
把 18 条重写全部临时关掉，再试一次
圈X → 设置 → 重写 → 远程列表，把开关全部关掉（不用删，随时能开回来）。然后重新打开刚才那个 App。
明显不卡了 → 就是 MitM 解密和脚本的开销。既然你感知不到去广告的收益，那就精简重写，只留你真用得上的几条件。
还是一样卡 → 去第 3 步。
3
手动锁定一个节点，排除自动切换
配置里「自动选择」策略组每 20 分钟测速一次，而且 tolerance=0（容差为零）—— 意味着只要另一个节点稍微快一点，它就会切过去。节点来回切会造成断流和卡顿。
在圈X 首页点「自动选择」那一组，手动指定一个你信得过的具体节点，用一段时间。
不卡了 → 就是切换抖动。把 tolerance 从 0 调大（比如 50 或 100），或者干脆一直用手动指定。
还卡 → 那问题在节点本身或你的网络环境。

五、我的建议

先做排查，再动配置。三步都在界面里点，随时可以退出来，零风险。

排查完大概率会得出同一个结论：那 18 条重写对你收益太低、成本太高，该砍。我倾向于给你砍到 3 到 5 条 —— 只留「去开屏」和你在用的那几个 App，其余全删。这样既省开销，又不用你再关心那些失效的条目。
